# AI command suggestions and assistant

Objective: inline command suggestions in the terminal (on by default, learning from the commands the user runs, optionally completed by an AI provider) and an on-demand AI assistant opened with a customizable shortcut. Branch `feat/ai-assist` (stacked on `feat/tools`). Delivery: ask-on-risk. Runners: Vitest (`pnpm vitest run`), cargo (`cargo test --manifest-path src-tauri/Cargo.toml`).

## Specs

- **S1 — Inline suggestions, on by default, learning from previous commands.** User: "Por defecto autocompletado en linea, tiene que ir aprendiendo de comandos anteriores, etc ...". Acceptance: while typing a command in a terminal pane (local, SSH, Telnet, Mosh, serial), a grey suggestion of the rest of the command is drawn after the cursor; it comes from the user's own command history (most recent and most frequent first, per host first then global), so it works with no AI configured. Accept the whole suggestion with Right Arrow (or End) when the cursor is at the end of the line; accept one word with Ctrl+Right; any other key keeps typing normally (Tab stays the shell's completion). History: every command sent with Enter is recorded locally per host in `history.json` in the app config directory (mode 0600, capped, deduplicated); never recorded: lines starting with a space, lines typed while the terminal shows a password/passphrase prompt, lines typed in full-screen programs (alternate screen: vim, less, top), multi-exec broadcast duplicates; the user can turn history off and clear it in Settings. Suggestions are hidden in full-screen programs and at password prompts. Assumption (not stated by the user): the typed line is tracked from the keys sent to the session since the last Enter (no shell integration needed); when it becomes uncertain (arrow keys through history, Ctrl+R, mouse paste with edits) suggestions pause until the next Enter.
- **S2 — AI completion of inline suggestions (optional).** User (earlier): "podriamos meterle dento la opcion de autocompletado con ia? añadiendo la api, por ejemplo con OpenAi, Anthropic o OpenCode". Acceptance: when an AI provider is configured and "AI suggestions" is on, and history gives no suggestion, after a short pause (debounced, ~400 ms, cancelled by further typing) PlexusTerm asks the provider for a completion of the current line, sending only: the typed line, the OS/shell kind if known, the current folder when known (OSC 7), and the last few history commands for that host (count configurable, can be 0); never terminal output. Requests are rate-limited; errors are silent except a small status hint. Providers: Anthropic (Messages API over HTTPS from the Rust backend), Google Gemini (user: "Mete tambien gemini"; API shape verified against Google's official docs at implementation time), OpenAI and any OpenAI-compatible endpoint (base URL configurable: OpenAI, Ollama, LM Studio, OpenRouter). OpenCode: see S6 (OpenCode Go provider). API keys only in the system keyring.
- **S3 — On-demand assistant with a customizable shortcut.** User: "y con una shortcut personalizable asistente bajo demanda". Acceptance: a shortcut (default Ctrl+Shift+Space, changeable in Settings, conflicts with existing app shortcuts refused) opens an assistant panel over the focused pane: the user describes what they want in natural language; the AI answers with a command (and a short explanation); **Insert** types the command into the focused pane without Enter (never runs anything); optional "Include selected text" sends the terminal selection (shown before sending). Uses the same provider settings; shows a clear message when no provider is configured.
- **S4 — Settings.** A new **AI** section in Settings: inline suggestions on/off (default on), command history on/off (default on) + Clear history, AI suggestions on/off (default off until a provider is configured), provider (Anthropic / Gemini / OpenAI / OpenAI-compatible), base URL (for compatible), model (free text with sensible default per provider), API key (stored in the keyring; field shows only whether a key is saved; Remove key), history commands sent as context (0–20, default 5), assistant shortcut. Defaults: Anthropic model `claude-opus-5-5` (the user may pick a faster/cheaper one); OpenAI model left for the user to fill.
- **S5 — The X opens the assistant and spins.** User: "Podriamos hacer que cuando le damos al shortcut para pasar al modo ia o al icono de la X que tambien activaria el modo IA, la X girara 360 grados." Acceptance: the PlexusTerm X mark in the toolbar is a button (accessible name "AI assistant", tooltip with the shortcut) that opens the assistant like the shortcut does; opening the assistant by either way makes the X rotate 360° once (smooth, ~600 ms, ease-out; a new trigger mid-spin restarts it cleanly); with `prefers-reduced-motion: reduce` there is no rotation.
- **S6 — OpenCode Go provider.** User error when using OpenCode Go as an OpenAI-compatible server: "fallo The OpenAI-compatible server rejected the request (HTTP 400): Request is missing x-opencode-session and cannot be routed efficiently. Please see https://opencode.ai/docs/go/#where-can-i-use-it". Per https://opencode.ai/docs/go/ (fetched 2026-10-15): chat completions at `https://opencode.ai/inference/go/v1/chat/completions`; clients must send a stable session ID per conversation in `x-opencode-session` and identify themselves with their own user agent (e.g. `my-coding-agent/1.0`); Go is meant for coding-agent traffic and is monitored for abuse; model list at `GET https://opencode.ai/inference/go/v1/models`. Acceptance: provider "opencode-go" (Settings: "OpenCode Go") using the OpenAI chat-completions shape at that URL with the key from the keyring (Bearer — the docs do not name the header; verify if possible), `x-opencode-session` = one stable ID per conversation (one per terminal pane for inline suggestions, one per assistant panel conversation), and every provider sends `User-Agent: PlexusTerm/<version>`; the openai-compatible provider also forwards a session ID header only when its base URL is OpenCode's; default model left empty for the user (suggest fetching the list). The Settings AI section notes OpenCode's usage terms for inline suggestions.
- **S7 — OpenCode Go with only an API key.** User: "consulta como funciona la api de opencode go, como obtiene los modelos, y si es posible qeu solo haga falta añadir api key, metelo como un proveedor" and "mira en context7". Findings (parent, 2026-10-15): (a) model list is public `GET https://opencode.ai/inference/go/v1/models` (OpenAI list format, no key); (b) each model uses one of four APIs, published per model by models.dev (`https://models.dev/api.json`, key `"opencode-go"` → `api: https://opencode.ai/inference/go/v1`, provider default npm `@ai-sdk/openai-compatible`; per model `provider.npm` overrides: `@ai-sdk/anthropic` → `/messages`, `@ai-sdk/openai` → `/responses`, `@ai-sdk/google` → `/models/<id>`; absent → `/chat/completions`), matching the docs table (context7 `/websites/opencode_ai` docs/go, `/anomalyco/opencode`); (c) auth: `Authorization: Bearer <key>` (Zen handler parses the authorization header); OpenCode's Anthropic client sends `x-api-key` for `/messages`. Acceptance: the user only enters the API key (Settings → AI → OpenCode Go); PlexusTerm fetches the model list (public endpoint) and the per-model format from models.dev in the backend, caches it (24 h, in the app cache/config dir, refresh button), offers the models in a dropdown with their names, and routes each request to the right endpoint and shape: chat completions (existing OpenAI-compatible code), Anthropic messages (send both `x-api-key` and `Authorization: Bearer`, `anthropic-version: 2023-06-01`, no Claude-only fields like `fallbacks`/`output_config` unless the model is a Claude model that supports them), OpenAI Responses (`POST /responses`, `input`, parse output text), Google (`/models/<id>:generateContent`-style per docs — verify; if unverifiable, mark the model "not supported yet" in the list instead of guessing). Every request carries `x-opencode-session` (per conversation) and `User-Agent: PlexusTerm/<version>`. If models.dev is unreachable, fall back to the public list with chat completions and a note.
- **S8 — The assistant answers anything, with an optional command.** User (after "hola" got "No command for this request."): "no tiene por que ser comandos" and "puede ser cualquier cosa". Acceptance: the assistant answers any question or request (explanations, steps, diagnosis of a selected error, general help, any topic) with a text answer, in the language the user wrote in (proposed by the parent and implied by the request); when a shell command fits, it is returned separately and shown in the command box with Insert (types it, no Enter) and Copy; when none fits there is no command box and no "No command for this request." line. The answer is plain text rendered safely (no HTML; line breaks kept; fenced code shown as monospace text blocks); untrusted-output rules stay: the command is one line without control characters, at most 2000 chars; the answer has control characters stripped (newlines and tabs kept) and a sane length cap. Inline suggestions (S2) are unchanged.
